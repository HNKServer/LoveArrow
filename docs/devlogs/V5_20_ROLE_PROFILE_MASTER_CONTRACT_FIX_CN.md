# NPPS4 v5.20：好友角色投影与客户端 Master 契约修复

## 本版基线

本版直接基于 v5.19 重新实现，不继承 7 月 25 日聊天中尚未完成验证和打包的半成品工作区。玩家账户数据库结构没有变化，也不需要迁移。

## 好友系统：主唱与引导员分离

本版不再让主唱和引导员互相充当回退候选：

- 好友列表与好友搜索的传统头像使用对方的引导员；
- 好友个人资料 `center_unit_info` 使用对方主力队伍第 5 位主唱；
- 好友个人资料 `navi_unit_info` 使用对方引导员；
- 演唱会好友助战使用对方主唱；
- 服装始终读取最终投影到的同一张持有卡，不能把引导员服装拼到主唱数据上；
- CN/GL 独有卡回退优先寻找同角色的安全卡，然后才寻找其他可安全投影的持有卡；
- 主唱与引导员的持有卡 ID 在彼此的回退过程中明确排除。

## 四个带签名的大感谢祭卡池

根据用户真机图片，本次纠正为：当前缺失的是 **Aqours 与 Liella!**，虹咲页面已经存在。

四个页面配置保持为：

- `5K / 1718`：μ's；
- `5L / 1719`：Aqours；
- `5M / 1720`：虹咲学园；
- `5N / 1721`：Liella!。

旧实现把运行时 `unit_type_m.member_category` 当作唯一分组来源。当前混合 Master 中该关系并不完整，导致页面候选经过过滤后，只要 SSR 或 UR 任一概率层为空，整个页面就会隐藏。

v5.20 改为：

1. 从 CN/GL 精确客户端能力目录读取 Unit 与角色分组；
2. 分别生成四组 SSR/UR 候选；
3. 再与当前运行时实际存在的 Unit 行取交集；
4. 只有真正没有可抽候选时才隐藏页面。

验证中 Aqours、Liella! 与原本存在的虹咲页面在 CN、GL 两端均能通过实际 Unit 交集。

## Android 首次工作区配置

v5.19 普通源码中的 `server_data.json` 已有 804 个 `name_cn`，但 Android 首次初始化使用的内嵌工作区载荷仍是旧副本，导致卸载重装后中文名称依然缺失。

本版重新构建内嵌工作区载荷：

- 内嵌 `server_data.json` 与普通源码逐字节一致；
- 内嵌 Schema 与普通源码逐字节一致；
- 干净安装可获得全部 804 个 `name_cn`；
- 四个大感谢祭页面均包含在首次工作区配置中。

## 贴纸商店、体力道具与专用饰品

- CN 贴纸商店名称由 **客户端 Profile** 决定，不再依赖账号语言；
- 当前精确契约保持 CN 52 种、GL 47 种体力恢复道具；
- GL 不会收到 CN 独有的 801–805；
- `LOVEARROWSHOOT` 把当前 Profile 支持的体力道具补到 9999，并在写入后重新查询验证；
- 普通招募券与 Item 5 补助券继续明确补到 9999；
- 专用饰品使用 CN 258 / GL 484 条客户端精确映射；
- 对应目标卡保证两张制作材料和一张装备用副本；
- 没有增加常驻的每用户衣柜、卡牌或饰品内存预读，仅沿用请求级缓存。
